## Architecture Overview

The community module system uses a **two-level registry** design:

```
Central index (maintained here)    Module maintainer's repo
────────────────────               ────────────────────────────────
registry.json                      registry.json (auto-maintained by CI)
[                                  {
  { "id": "00000001",                "id": "my_module",
    "repo": "github.com/..." }  →    "name": "My Module",
]                                    "latestVersion": "1.2.0",
                                     "downloads": { ... },
                                     "sha256": { ... }
                                   }
```

- **Central index**: stores only a sequence number and repo URL. A PR is needed **only once**, when first registering.
- **Module metadata**: written automatically by CI into the maintainer's `registry.json`. To release a new version, just bump `version` in `Cargo.toml` and push — no manual file editing needed.

## Step 1: Create a module repository

1. Create a **public repository** on GitHub, recommended name: `stripchat-pp-<your-module-id>`
2. Copy the contents of [module-template/](https://github.com/ChanTrail/StripchatRecorderCommunity/tree/master/module-template) into your repo
3. Edit these files once:
   - `Cargo.toml`: change `name` (matching your module ID) and `version`
   - `src/main.rs`: replace `my_module` with your module ID and implement `run()`
   - `registry.json`: fill in `id`, `name`, `description`, `author`, `tags` (other fields are auto-managed by CI)
   - Both workflow files: update `MODULE_NAME` at the top

See the [module development guide](module-development.en.md) for the full stdin/stdout protocol.

---

## Step 2: Configure RELEASE_PAT

Add a `RELEASE_PAT` secret to the repository:

1. GitHub avatar (top-right) → **Settings** → **Developer settings** → **Personal access tokens** → **Tokens (classic)**
2. Click **Generate new token (classic)**, check **repo** scope, click **Generate token**
3. Copy the generated token (`ghp_xxx...`) — it's only shown once
4. Go to the module repo → **Settings → Secrets → Actions** → **New repository secret**
5. Set **Name** to `RELEASE_PAT`, paste the token into **Secret**, click **Add secret**

> **Why is a PAT required?**  
> Tags pushed by the default `GITHUB_TOKEN` do not trigger other workflows (GitHub security restriction).  
> A PAT-pushed tag is what allows `release.yml` to be triggered.

## Step 3: Initialize registry.json

The template's `registry.json` only needs three fields filled in — **everything else is auto-generated by the Release workflow**:

```json
{
  "description": "What your module does",
  "tags": ["notify", "upload"],
  "license": "MIT"
}
```

The Release workflow derives and writes all other fields automatically:

| Field           | Source |
|-----------------|--------|
| `id`            | `Cargo.toml` `name` |
| `name`          | Title Case form of `id` (`my_module` → `My Module`) |
| `author`        | Repository owner (`owner` from `owner/repo`) |
| `latestVersion` | `Cargo.toml` `version` |
| `downloads`     | Constructed from the tag and platform names |
| `sha256`        | Read from the `.sha256` files produced by the build job |

### Supported platform identifiers

| Identifier       | Platform                  |
|------------------|---------------------------|
| `windows-x86_64` | Windows 64-bit            |
| `linux-x86_64`   | Linux x86_64              |
| `linux-aarch64`  | Linux ARM64               |
| `darwin-x86_64`  | macOS Intel               |
| `darwin-aarch64` | macOS Apple Silicon       |

## Full Release Flow

After setup, **releasing a new version takes two steps**:

```bash
# 1. Bump the version field in Cargo.toml
# 2. Push to main
git add Cargo.toml
git commit -m "chore: bump version to 1.0.0"
git push origin main
```

Everything else is automatic:

```
push main
   ↓
ci.yml: check / clippy / test pass
   ↓
ci.yml: reads Cargo.toml version → pushes tag (via RELEASE_PAT)
   ↓
release.yml: multi-platform build + sha256 computation
   ↓
release.yml: updates registry.json (latestVersion / downloads / sha256) with jq
            and commits back to main via RELEASE_PAT
   ↓
release.yml: creates GitHub Release and uploads all artifacts
   ↓
StripchatRecorder picks up the new version on the next refresh
```

## Step 4: Register in the central index (once only)

1. Fork [StripchatRecorderCommunity](https://github.com/ChanTrail/StripchatRecorderCommunity)
2. Append one line to `registry.json`:

```json
{ "id": "00000NNN", "repo": "https://github.com/your-username/stripchat-pp-your-module" }
```

Take the current highest `id` + 1, zero-padded to 8 digits (e.g. if the current max is `00000003`, add `00000004`).

3. Open a PR with the title: `Add module: {your_module_id}`

## Upgrading a version (fully self-managed)

Bump `version` in `Cargo.toml` and push. **Nothing else is needed.**
